# 歌词图片皮肤制作指南

> 适用版本：LyricShareKit `schemaVersion = 1`、`ENGINE_VERSION = 1`
> 相关代码：`skin/SkinSpec.kt`（模型）、`skin/SkinParser.kt`（解析）、`render/LyricImageRenderer.kt`（绘制）

---

## 1. 原理：皮肤是数据，不是代码

一份皮肤 = **一个 `skin.json` + 可选图片/字体资源**。

引擎拿到皮肤后做两件事：

1. **度量**：把「流式元素」从上往下排一遍，算出每个元素的像素尺寸和画布总高；
2. **绘制**：先铺背景，再按数组顺序把元素画到 `Bitmap` 上。

和「下载一个可执行插件（dex）、加载自定义 Fragment 再 `View.draw()` 截图」那套做法相比：

| | 代码插件方案 | 本方案（数据皮肤） |
|---|---|---|
| 皮肤内容 | 可执行 dex + 自定义 Fragment | JSON + 图片 + 字体 |
| 分辨率 | 依赖屏幕密度，预览=屏幕尺寸 | 预览/导出**同分辨率同引擎**，界面只缩放显示 |
| 长歌词 | 受 ScrollView 可见区域影响 | 自动高度，多长都完整 |
| 上线 | 要发版/审核 dex，加载失败会崩页面 | 改 JSON 即可热更，解析失败自动忽略该皮肤 |
| 安全 | 等于在宿主进程跑第三方代码 | 无代码执行，只有资源读取（且防目录穿越） |
| 预览图 | 需要另做 | 引擎用真实数据实时渲染缩略图 |

## 2. 目录结构与打包

```
my_skin/
├── skin.json        # 必须，UTF-8，无注释（标准 JSON）
├── preview.png      # 可选：列表缩略图。不给我也会用引擎实时渲染，所以通常不用给
├── images/          # 皮肤自带图片：背景、装饰框、logo
│   ├── bg.jpg
│   └── logo.png
└── fonts/           # 皮肤自带字体（可选）
    └── serif.otf
```

打包与下发：

```bash
cd my_skin && zip -r ../my_skin.zip . -x ".*"
md5sum ../my_skin.zip        # 服务端返回这个值，客户端 installFromZip 时校验
```

- zip 里**可以**带一层顶层目录（安装时会自动找到 `skin.json`）；
- 客户端安装：`LyricShareKit.installSkin(context, zipFile, expectedMd5)`；
- 内置皮肤直接放到 `app/src/main/assets/skins/<id>/`。

## 3. 坐标系：一切都是「参考画布宽度」的像素

| 概念 | 说明 |
|---|---|
| `canvas.width` | 参考画布宽度，默认 **1080**。所有数值（字号、间距、圆角…）都以它为基准 |
| 缩放 | 渲染时 `scale = 输出宽度 / canvas.width`，整体等比缩放。**预览和导出用同一个输出宽度**（默认就是 1080），界面负责缩放显示，所以预览清晰、与出图零偏差 |
| `canvas.height` | `null` = 按内容自适应（推荐），数字 = 固定高度（超出的内容会被裁掉） |
| `canvas.minHeight` | 自适应时的**最小**高度。⚠️ 慎用：设太大时，歌词很少也会被撑成一张大卡片。一般**不要写**，让画布贴合内容 |
| `canvas.padding` | 四边内边距，流式元素默认从这里开始排 |

**元素定位有两种模式**（同一个皮肤里可以混用）：

| 模式 | 写法 | 用途 |
|---|---|---|
| 流式（推荐） | 不写 `y` | 元素依次向下堆叠，用 `marginTop/marginBottom` 控制间距，高度自动算 |
| 绝对 | `"y": 480` / `"y": "bottom"` / `"y": "center"` | 需要精确压位（角标、贴底二维码）时用 |

水平方向：

| 写法 | 含义 |
|---|---|
| `"x": 72` | 距左边距 72（会叠加 `canvas.padding.left`） |
| `"x": "center"` | 水平居中（`marginLeft/marginRight` 可用于微调） |
| `"x": "right"` | 贴右边（减去 `canvas.padding.right` 和 `marginRight`） |

## 4. 字段速查

### 4.1 顶层

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `id` | string | — | 唯一标识，只允许 `A-Za-z0-9_-`，≤64 字符 |
| `name` | string | id | 列表里显示的名字 |
| `schemaVersion` | int | 1 | 皮肤格式版本，大于引擎支持版本会被忽略 |
| `minEngineVersion` | int | 1 | 要求的最低引擎版本 |
| `canvas` | object | — | 见下 |
| `defaults` | object | — | 文本类元素的默认样式 |
| `elements` | array | `[]` | **数组顺序 = 绘制顺序**（后画的盖在上面） |

### 4.2 `canvas`

| 字段 | 默认 | 说明 |
|---|---|---|
| `width` | 1080 | 参考宽度 |
| `height` | null | null = 自适应 |
| `minHeight` | 0 | 自适应时的最小高度 |
| `padding` | `{left:72,top:96,right:72,bottom:96}` | 也支持 `l/t/r/b` 简写 |
| `background` | 纯白 | 见下 |

`background`：

| 字段 | 说明 |
|---|---|
| `type` | `color` / `gradient` / `image` |
| `color` | **`#RRGGBB`**（推荐，不透明）；也兼容 `#RGB` / `#AARRGGBB`，支持 `none`/`transparent` |
| `colors` + `angle` | 渐变：颜色数组（≥2）+ 角度（0 = 从上到下，90 = 从左到右） |
| `src` | `image` 类型：皮肤内相对路径，如 `images/bg.jpg` |
| `useCover` | `image` 类型：用**运行时封面**当背景（做模糊大图背景就靠它） |
| `blur` | 模糊半径（参考像素），建议 30~60 |
| `scrim` | 压暗层：`{ "color": "#000000", "opacity": 0.7 }`（保证文字可读） |
| `scaleType` | `centerCrop` / `fitCenter` |

### 4.3 `defaults`（文本默认样式）

| 字段 | 默认 |
|---|---|
| `color` | `#000000` |
| `size` | 44 |
| `lineSpacing` | 20（行距，累加值） |
| `letterSpacing` | 0（字距，参考像素） |
| `align` | `left`（`left`/`center`/`right`） |
| `font` | 见 §7 |

### 4.4 元素公共字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | string | `text` / `lyric` / `image` / `qrcode` / `divider` / `spacer` |
| `role` | string | 语义角色：`cover`（用运行时封面）、`brand`（"来自 XXX"，**默认不绘制**）、自定义 |
| `x` / `y` | number \| string | 见 §3；不写 `y` 即流式 |
| `width` / `height` | int | 元素尺寸；文本不给 `width` 时占满内容宽度 |
| `margin` | object | `{left,top,right,bottom}`，也可用 `marginTop` 等扁平写法 |
| `align` | string | 仅文本：段内对齐，覆盖 `defaults.align` |
| `size` / `color` | number / color | 覆盖默认字号/颜色 |
| `lineSpacing` / `letterSpacing` | number | 覆盖默认行距/字距 |
| `maxLines` / `ellipsize` | int / bool | 最大行数 / 超出是否省略。⚠️ **歌词和标题建议都不要写 `maxLines`**：不写就是"有多少显示多少"，画布自动加高；写了超出部分就会变成 `…` |
| `cornerRadius` / `circle` | int / bool | 图片圆角 / 圆形裁剪 |
| `scaleType` | string | 图片：`centerCrop`（默认）/ `fitCenter` |
| `shadow` | object | `{radius, dx, dy, color, opacity}`，图片和文字都支持 |
| `blur` | int | 图片模糊半径 |
| `scrim` | color/object | 图片上叠的压暗层：`{ "color": "#000000", "opacity": 0.25 }` |

### 4.4.1 颜色怎么写

| 需求 | 写法 |
|---|---|
| 纯色（**绝大多数情况**） | `"color": "#333333"` —— 六位即可，出图不需要 alpha 通道 |
| 半透明压暗层 | `"scrim": { "color": "#000000", "opacity": 0.7 }` |
| 半透明阴影 | `"shadow": { "radius": 20, "dy": 8, "color": "#000000", "opacity": 0.15 }` |
| 透明 | `"color": "none"` 或 `"transparent"` |
| 兼容写法 | `"#AARRGGBB"`（alpha 写进颜色）仍可解析，但规范和示例一律不用 |

### 4.4.2 可编辑项 `editable`：**控件表**（界面完全数据驱动）

模块里没有"封面面板 / 二维码面板 / 字体面板"这种东西，界面只做两件事：

1. 把皮肤里**所有** `editable` 扫出来 → 一项渲染一个入口（名字 = `label`，顺序 = `order`）；
2. 打开某一项时，**按它的控件表逐条渲染控件** —— `control` 决定用什么组件，`property` 决定改哪个属性。

所以"给用户开放什么、用什么控件、范围多少"完全由皮肤决定；皮肤不声明就没有入口。
可以写在**任意元素** / `canvas.background` / `defaults` 上。

```jsonc
{
  "elements": [
    { "type": "qrcode", "width": 156, "height": 156, "x": "center", "color": "#111111",
      "qr": { "errorCorrection": "M", "backgroundColor": "#FFFFFF" },
      "editable": {
        "id": "qr", "order": 4, "label": "二维码",
        "controls": [
          { "property": "visible",    "label": "显示二维码" },
          { "property": "placement",  "label": "放置位置", "options": ["left","bottom","right"] },
          { "property": "color",      "label": "二维码颜色" },
          { "property": "background", "label": "底色", "allowTransparent": true },
          { "property": "scale",      "label": "大小", "range": [0.5, 2.0] }
        ]
      } }
  ]
}
```

#### 属性表（`property`）

| 属性 | 引擎怎么通用地应用它 | 哪些类型支持 |
|---|---|---|
| `visible` | 显隐；关掉后**不占空间**，后面的内容自动上移 | 全部 |
| `source` | 换掉元素的"源图"（图片内容 / 背景图 / 二维码中心 logo） | image / qrcode |
| `shape` | 形状：`rounded` 圆角、`rect` 直角、`circle` 圆形 | image |
| `scale` | 乘到元素的**生效尺寸**上：文字=字号、图片=占位、二维码=码块、分割线=粗细、组合=整体 | 全部 |
| `offset_x` / `offset_y` | 位移，相对画布宽/高的比例 | 除 spacer 外全部 |
| `placement` | 锚点：`left`=左下、`bottom`=下方、`right`=右下、`top`=上方、`center`=正中；吸附到对应位置并脱离流式排版 | image / qrcode / group |
| `color` | 主色：文本=字色、二维码=码点色、分割线=线色、图片=整体着色 | 除 spacer 外全部 |
| `background` | 元素**背后**的底色（二维码静默区 / 文字高亮底 / 图片底板），可设透明 | image / text / lyric / qrcode / group |
| `font` | 字体（系统默认 / 皮肤内置 / 已导入 / 从文件选择） | text / lyric |

#### 控件表（`control`）

| 控件 | 组件 | 需要的字段 |
|---|---|---|
| `switch` | 开关 | — |
| `slider` | 滑杆 | `range: [min,max]`（如 `[0.5,2.0]`）；**`step`：颗粒度**（不写按 1%，`0` = 连续不吸附） |
| `color` | 一排色卡（第一张斜杠 = 跟随皮肤） | `allowTransparent`（给"透明"档）、`allowNone`（默认 true 显示斜杠）、`shape` 等 |
| `enum` | 一排胶囊 | `options: ["left","bottom","right", ...]`（锚点类不用给 `skin`：**没选就是跟随皮肤声明的位置**）。注意 `center` = **画面正中**（两轴居中），「贴底居中」要用 `bottom` |
| `font` | 字体列表 | — |
| （全局）`step` | — | `slider` 的颗粒度由皮肤定；`allowTransparent` 给底色加"透明"档 |
| `image` | 「从相册选择」 | — |
| `shape` | 形状胶囊 | 可选项写在控件的 `options`（如 `["rounded","rect","circle"]`），不写给三种常规值 |
| `text` | **文本框**（可输入文字） | `hint`：输入提示。写进去的内容仍支持占位符与日期时间参数 |

不写 `control` 时按 `property` 自动推断；**同样一个属性可以声明多次**（例如两个 `slider` 分别给字号和行距——行距暂未开放）。

#### 兼容：旧式开关

老写法（`replace` / `visibility` / `shape` / `size` / `move` / `color` / `background` / `font`，或整段 `"editable": true`）
仍然可用：引擎会按**元素类型能力表**（图片能着色能裁形状、文本能换字体…）把它展开成上面这张控件表。
新皮肤建议直接写 `controls`，控制更精确。

> **用户调整会被记住**：模块会把用户对每个可编辑项的调整（含从相册换的图）**按皮肤**存到本地，
> 下次进页面自动读回。所以皮肤作者不用自己处理"要不要保存"；用户在面板里点「重置」即清掉该项。
>
> 「跟随播放页」色卡：声明了 `background` 属性时，色卡行**第一张**是宿主传进来的播放页取色
> （水滴图标画在色块内部）；宿主没传就自动不显示。

### 4.4.2.1 文字里的参数（占位符 + 日期时间）

`text` 类型元素（含文本框输入的内容）里可以写这些参数，出图时会被替换：

| 参数 | 含义 |
|---|---|
| `{title}` `{artists}` `{album}` | 歌名 / 歌手 / 专辑 |
| `{lines}` `{firstLine}` `{count}` `{brand}` | 全部歌词 / 首行 / 行数 / 来源文案 |
| `YYYY` `YY` `MM` `dd` `HH` `hh` `mm` `ss` | 年 / 两位年 / 月 / 日 / 24 小时 / 12 小时 / 分 / 秒（`{YYYY}` 与裸写都认；裸写只在独立成词时替换） |
| `{date}` `{time}` | `YYYY/MM/dd` / `HH:mm:ss` |

时间取**数据构造时固定下来的时间戳**，所以预览与导出是同一个时刻。

```jsonc
{ "type": "text", "text": "{title} · YYYY/MM/dd HH:mm", "size": 28,
  "editable": { "id": "stamp", "order": 6, "label": "时间戳",
    "controls": [ { "property": "text", "control": "text", "label": "文字",
                    "hint": "可用 {title}；日期 YYYY/MM/dd HH:mm:ss" } ] } }
```

### 4.4.3 组合类型 `group`：皮肤自己"拼"新类型

引擎提供的**元素类型**是固定的（文本/歌词/图片/二维码/分割线/留白），因为"把内容画出来"是算法。
但皮肤可以把它们**组合**成一个新的整体 —— 这正是"不限制皮肤发挥"的那一半：

```jsonc
{
  "type": "group",
  "orientation": "row",          // row 一行 / column 一列 / stack 叠放
  "gap": 24,                     // 子元素间距（参考画布像素）
  "crossAlign": "center",        // 交叉轴对齐：start / center / end
  "x": "center", "marginTop": 48,
  "editable": {
    "id": "meta", "order": 15, "label": "歌名",
    "controls": [
      { "property": "visible", "control": "switch" },
      { "property": "scale",   "control": "slider", "range": [0.6, 1.6] },
      { "property": "offset_x","control": "slider", "range": [-0.25, 0.25] }
    ]
  },
  "children": [
    { "type": "text", "role": "title",   "text": "{title}",   "size": 52, "color": "#111111" },
    { "type": "text", "role": "artists", "text": "{artists}", "size": 34, "color": "#8A8A8A" }
  ]
}
```

规则：

- `orientation: "row"` 时**写了 `width` 的子元素**（图片/二维码按内容尺寸）先占位，剩余宽度平分给"弹性"子元素；
  纵向/叠放时弹性子元素直接占满可用宽度。这样「歌名 + 二维码」这类信息条能自然排开。
- 组合**整体**参与外层流式排版（`x`/`marginTop` 等照常用）。
- **子元素是完整元素**：可以有自己的 `editable`（显隐 / 缩放 / 位移 / 颜色 / 底色 / **`placement` 锚点**），
  引擎按同一套属性语义递归应用 —— 所以"二维码在这行里切左下/右下"也是皮肤声明 + 用户可切，
  不需要引擎为某个皮肤写特例。
- 子元素的位置有两种表达，**可以同时用**（位置不限于预设锚点）：
  `offset_x` / `offset_y` 是**连续微调**（相对画布宽/高的比例，如 `-0.3 ~ 0.3`），
  `placement` 是**吸附到父组合的某一端**：
  `row` 里 `left` → 贴左端、`right` → 贴右端（其余子元素在中间流动）；没写 `placement` 就按声明顺序流动。
- 子元素可以继续嵌套 `group`（`column` 套 `row` 就是"左边两行字、右边一个码"这种版式）。
- 组合里"弹性宽度"的分法：写了 `width` 的子元素（图片/二维码按内容尺寸）先占位，
  剩下的宽度平分给弹性子元素。

内置皮肤 `default_light` 就把「歌名 + 歌手」拼成了一个 `column` 组合（入口叫「歌名」）。

## 6. 关于「来自 XXX」和二维码

- **来源文案默认不显示，也不预留空间。**
  两种写法都不会占位：
  1. 皮肤里根本不写这类元素（推荐）；
  2. 写了但标 `"role": "brand"`，引擎默认 `showBrandElement = false` 会把它整条过滤掉，
     它是**不参与度量**的，所以下方元素会自然上移，不会留一块空白。
- **二维码**：`type: "qrcode"`。用户在页面上关掉二维码时，该元素同样整条不参与布局。
  `qr.label` 默认 `null`，也就是不会出现"扫码听歌"这类文字，更不会为它留高度。

## 7. 字体

三种用法：

```jsonc
// ① 皮肤自带字体（推荐给标题用，正文用系统字体以控制包体积）
"font": { "source": "assets", "value": "fonts/serif.otf", "bold": false }

// ② 系统字体族（零体积，最安全）
"font": { "source": "system", "value": "sans-serif-medium" }

// ③ 跟随引擎默认（宿主可用 LyricShareConfig.defaultFont 换成品牌字体）
"font": { "source": "default" }
```

优先级：**用户在页面上选的字体（`RenderOptions.fontOverride`） > 元素字体 > `defaults.font` > 引擎默认字体**。

字体文件解析失败会自动回落默认字体，绝不会因为字体把整张图渲染挂掉。

## 8. 制作流程（设计 → 上线）

1. **设计**：Figma/Sketch 建 1080 宽的画板，按 §9 的规范摆元素；不需要的图层不要导出。
2. **导出资源**：背景/装饰导出 PNG（1080 宽、≤500KB 为宜），放进 `images/`。
3. **写 `skin.json`**：先只写 3~4 个元素跑通，再逐步加。
4. **本地预览**（不用装机也能看）：
   - 内置方式：把目录放到 `app/src/main/assets/skins/<id>/`；
   - 侧载方式：打成 zip 调 `LyricShareKit.installSkin(context, zip)`；
   - 页面皮肤列表里的缩略图就是引擎实时渲染的，所以**不需要单独准备预览图**。
5. **快速出大图自检**：
   ```kotlin
   val bmp = LyricShareKit.render(context, request, skinId = "my_skin", widthPx = 1080)
   // 写到文件看一眼，或直接 LyricShareKit.saveToGallery(context, bmp)
   ```
   > 顺带一提：生成页的预览就是按这个宽度（皮肤参考宽度）渲染的，界面只做缩放，
   > 所以**你在页面上看到的 = 最终导出的**，不需要靠"导出后再看一眼"来校验视觉。
6. **打包下发**：zip + `fileMd5` + `fileLength` + 缩略信息，服务端给客户端一份列表。
7. **灰度/回滚**：
   - `id` 不变时覆盖安装即热更；
   - 出问题的皮肤 `SkinRepository.remove(id)` 即可回退到内置皮肤；
   - 提高 `minEngineVersion` 可以让老版本客户端自动忽略新皮肤，而不是渲染出错图。

## 9. 设计规范建议（1080 基准）

| 项 | 建议 |
|---|---|
| 安全边距 | ≥ 64（全出血皮肤除外，但文字距边 ≥ 64） |
| 字号梯度 | 歌名 56 / 副标题 34 / 正文 42~48 / 注释 28~30，少用 5 档以上 |
| 歌词行数 | `maxLines` 10~14；行距 = 字号的 0.65~0.8 倍 |
| 封面比例 | 1:1（大图）或 1:1 圆形；一张图里不要出现两种封面形状 |
| 对比度 | 文字与背景 ≥ 4.5:1；深色背景务必叠 `scrim` |
| 二维码 | 边长 ≥ 132，四周留白 ≥ 24，别压在有纹理的图片上（必要时加白底 `quietZone`） |
| 圆角 | 全站统一：大图 24，小卡片 16，圆形用 `circle` |

## 10. 引擎能力边界

**已支持**：纯色/线性渐变/图片（模糊+压暗）背景；图片（圆角、圆形、阴影、centerCrop/fitCenter、模糊、压暗）；
文本（对齐、行距、字距、阴影、占位符、最大行数、省略号）；歌词多行；二维码（纠错级别、静默区、中心 logo）；
分隔线；留白；绝对/流式混排；**用户可编辑项声明（换图/显隐/形状/大小/位置）**。

**未支持**（需要时按下面的方式扩展，不用改皮肤协议）：

- 动画 / 多帧导出；
- 图层混合模式、路径绘制、文字沿路径；
- 复杂裁剪（多边形、蒙版）。

**扩展方式**：在 `ElementType` 里加一个类型 → 在 `SkinParser.parseElement` 补字段 → 在
`LyricImageRenderer.measure` / `drawElement` 各加一个分支即可。老皮肤不受影响（未知 `type` 会退化成 `text` 并因空文本被忽略）。

## 11. 调试清单

| 现象 | 原因 |
|---|---|
| 元素没画出来 | 字段名拼错（解析器忽略未知字段）；`text` 展开后为空（空文本元素会被整条丢弃） |
| 位置差了 3 倍 | 把 dp 当成参考像素写了 —— 皮肤里一律用「1080 基准像素」，不要写 dp |
| 文字换行很怪 | 没给 `width`，默认占满内容宽度；需要窄栏就显式给 `width` |
| 长歌词被截断 | `maxLines` 太小 / `canvas.height` 写死导致溢出被裁 |
| 背景糊得不够 | `blur` 是相对**参考宽度**的半径，1080 下建议 30~60 |
| 压暗层/阴影不生效 | 写成了 8 位 `#AARRGGBB`？规范是用 `"opacity": 0~1` 独立字段；另外 `opacity` 要写在**同一个对象里**（`scrim` 对象内、`shadow` 对象内） |
| 二维码扫不出来 | 静默区为 0 又贴在花哨背景上；或 `logoScale` 超过 0.22 却没抬到 H 级纠错 |
